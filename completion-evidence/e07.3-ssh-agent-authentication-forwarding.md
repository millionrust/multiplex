## Delivered

- Added backward-compatible local SSH-agent authentication across saved profiles, drafts,
  connection requests, jump chains, workspace restore, and SSH-config `IdentityAgent` import.
- Added one bounded authentication adapter shared by interactive SSH, remote exec, jump hosts,
  and SFTP. It accepts only a direct, owned Unix socket and limits agent operations to five
  seconds and 64 deterministic identity attempts.
- Added a separate, default-off `Connect + Forward Agent Once` action. Approval is consumed while
  spawning the pane and is absent from stored pane requests, restore state, reconnect, remote
  exec, SFTP, and intermediate jump hops.
- Added honest editor availability feedback without exposing socket paths or copying private keys.
- Rejects mobile-vault export of agent-backed hosts instead of silently changing authentication.
- Added the platform decision and repeatable verification gate in
  `docs/decisions/ssh-agent-authentication-forwarding.md` and
  `scripts/verify-ssh-agent-access.sh`.

## Security And Platform Boundary

The implemented agent transport is intentionally Unix-only and makes no Windows agent claim.
Agent authentication never implies forwarding and never falls back to passwords or key files.
Socket paths, identity inventories, key blobs, signatures, and agent traffic are not persisted or
logged. Forwarding proxies only the explicitly approved target session and expires before any
reconnect or restore.

Known repository warnings from legacy `objc` macros, dead code, and future-incompatible
dependencies remain unchanged; the changed-line Clippy gate is clean.
