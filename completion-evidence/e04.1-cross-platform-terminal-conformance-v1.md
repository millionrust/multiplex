# E04.1 Cross-platform terminal conformance v1 completion evidence

## Result

Rust desktop, native Swift, and native Kotlin now consume one versioned, sanitized
terminal corpus and produce the same v1 signature for visible rows, cursor position and
visibility, application-cursor mode, alternate-screen state and restoration, bracketed
paste, mouse tracking/encoding, and bounded primary-screen scrollback. Every case is
also replayed at every byte split, including splits inside UTF-8 and control sequences.

The canonical fixture is
`tests/fixtures/terminal/terminal-conformance-v1.json`. Exact copies live in the two
native repositories, and `scripts/sync-terminal-conformance-fixture.sh --check` fails
closed if either copy drifts.

Implementation commits, all without coauthor trailers:

- Rust: `4b02f5f` (`test(terminal): add cross-platform conformance corpus`)
- Swift: `7e54558` (`feat(terminal): align Swift VT mode conformance`)
- Kotlin: `689baf8` (`feat(terminal): align Kotlin VT mode conformance`)

Clean baselines were Rust `9a7f978`, Swift `4cf3328`, and Kotlin `648522d`.

## Delivered behavior

- Rust exposes test-only cursor visibility and position and validates the production
  `vt100` wrapper against all six fixture cases and every chunk boundary.
- Swift and Kotlin production bounded parsers now model the closed supported private
  mode set: DEC 1, 9, 25, 1000, 1002, 1003, 1005, 1006, 1049, and 2004.
- Both native parsers save and restore the primary screen for DEC 1049, keep alternate
  output out of primary scrollback, report viewport-relative cursor coordinates, and
  preserve inert OSC handling and existing bounds.
- Swift executes the production parser in a host-side runtime harness; Kotlin executes
  the production parser in the controller JVM unit-test target.

## Acceptance mapping

- Normal: printable text, CR/LF, cursor movement, erase, save/restore, and private modes
  produce identical signatures on all three production parsers.
- Boundary: one-byte and every possible split, split UTF-8, bounded scrollback, parser
  carry, and frame limits pass.
- Malformed/external: OSC remains inert and cannot enter visible cells; unsupported
  behavior remains outside the closed v1 mode model.
- Recovery/idempotency: leaving alternate screen restores the saved primary cells and
  cursor and resets alternate/mouse/bracketed modes exactly; whole and chunked feeds are
  equivalent.
- Cancellation/timeout/race: N/A. This leaf is deterministic in-memory parsing with no
  task, process, clock, transport, or cancellation owner.
- Permission/locked dependency: N/A. Fixtures contain no secrets and require no user
  files, credentials, devices, or network access.
- Accessibility/localization/UI: N/A. No rendered UI or user-facing copy changed.
- Security/privacy: fixtures are synthetic and sanitized; OSC payloads are inert; no
  logging, storage, protocol, credential, or trust boundary changed.
- Performance: existing parser resource caps are asserted. No new throughput target was
  introduced or claimed by E04.1.
