# E06.2 desktop route coordinator and recovery UX

Date: 2026-08-30
Status: complete

## Delivered

- Added one UI-independent desktop coordinator for local IPC, private LAN/VPN,
  user-provided SSH, and optional self-hosted relay routes.
- Kept transport ownership in the existing IPC, listener, SSH, and relay modules. The
  coordinator returns typed start, disconnect, input cleanup, writer release, retry, and
  mutation-reconciliation plans instead of owning sockets or processes.
- Added explicit route selection and switch confirmation. Failures and availability changes
  never select or start another route automatically.
- Projected configuration, phase, capability, trust, terminal-authority, and recovery state
  for UI consumers, including Configure, Retry, Reauthorize, Cancel, Enable, and no-action.
- Mapped existing SSH and relay client states into the shared route phases.
- Extended the shared state contract for runtime availability loss and authorization
  restoration. Revocation and explicit disable take precedence over endpoint changes, so
  restoring configuration cannot bypass reauthorization or user intent.
- Made repeated availability signals idempotent and preserved unknown mutation completion as
  command-ID reconciliation rather than replay.
- Added a four-route lifecycle matrix covering normal connection, degradation, reconnect,
  cancellation, revocation, and every explicit cross-route switch pair.

## Scope Notes

This leaf coordinates existing desktop routes and exposes truthful recovery projections. It
does not operate a public relay, create an account, weaken inner Controller authentication,
or transfer transport ownership. Native Apple, Android, and synchronized acceptance work
remain E06.3 through E06.5.
