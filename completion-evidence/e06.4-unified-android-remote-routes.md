# E06.4 unified Android remote routes

Date: 2026-08-30
Status: complete

## Delivered

- Ported the canonical route policy, trust layers, capabilities, configuration requirements,
  phases, transition reducer, switch rules, mutation completion rules, and no-fallback
  guarantees to serializable Kotlin models.
- Added an Android route coordinator for private LAN/VPN, Controller over SSH, and optional
  self-hosted relay. It preserves unavailable persisted selections, requires explicit switch
  confirmation, treats repeated availability events idempotently, and keeps revocation or
  disablement dominant over configuration changes.
- Added route-keyed `ControllerConnecting` ownership. Fleet refresh, terminal attach, writer
  acquisition/release, input, resize, retry, background cancellation, and teardown resolve
  through the selected or captured source route only.
- Captured route ownership in every active terminal runtime so a later selection cannot send
  terminal mutations to another adapter. Route switches release a held writer, clear pending
  input and resize state, cancel only the source, retain no mutation for replay, and never
  start or fall back to another route implicitly.
- Added a responsive Compose route selector under Devices with persisted selection, explicit
  confirmation, and visible ready, online, reconnecting, degraded, revoked, selected, and
  unavailable states on phones and tablets.
- Added validated SSH and `wss` relay descriptors containing credential references only.
  Android Keystore secret accounts are scoped by Host, route, credential purpose, and
  reference, preventing cross-route or cross-Host secret aliasing.
- Kept direct SSH Connections distinct from Controller-over-SSH Device access and retained
  the existing Controller authentication, replay, terminal, and single-writer contracts.

## Runtime And Product Limits

No Android hardware or emulator was attached, so physical touch, rotation, and accessibility
interaction were not exercised in this environment. Compose compilation, lint, unit tests,
adaptive layout structure, and the universal APK gate passed.

The production Device transport set currently installs private LAN/VPN only. Direct SSH is a
working route under Connections, not a substitute for Controller-over-SSH. SSH Controller and
self-hosted relay remain visibly unconfigured until dedicated adapters preserve Controller
authentication, capability negotiation, host-key/SPKI pinning, route-scoped cancellation,
and writer semantics. E06.5 carries this truthful limitation into shared acceptance evidence.
