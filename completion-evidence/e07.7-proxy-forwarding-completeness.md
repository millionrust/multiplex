# E07.7 Proxy and Forwarding Completeness

- Status: complete
- Completed: 2026-08-30
- Branch: `test`

## Delivered

- Added backward-compatible typed Direct, SOCKS5, and HTTP CONNECT routing to saved hosts, drafts,
  connection requests, workspace restore, canvas launches, and nested jump-host persistence.
- Added bounded SOCKS5 and HTTP CONNECT handshakes with remote domain routing, strict framing,
  15-second total timeout, 16 KiB HTTP header cap, cancellation cleanup, and no banner over-read.
- Routed interactive SSH, SFTP, remote execution, key deployment, and the outermost jump hop through
  the shared first-hop implementation while retaining end-to-end SSH verification.
- Added an explicit Network Route editor with conditional proxy endpoint fields and a visible
  unsupported-authentication boundary.
- Fixed local/dynamic forwarding listener ownership so disconnect, cancellation, and partial
  startup failure release bound ports.
- Documented the security contract in `docs/decisions/proxy-routing.md` and added
  `scripts/verify-proxy-routing.sh`.

## Acceptance Evidence

- Unit tests cover SOCKS domain encoding, HTTP tunnel-byte preservation, malformed and denied
  responses, authentication challenges, timeout, cancellation, redaction, old-state defaults,
  validation, and restore round-trip.
- Docker acceptance proves both proxy protocols for terminal, remote exec, and a first jump hop
  whose configured hostname cannot resolve directly.
- Docker acceptance proves SFTP through HTTP CONNECT.
- Forwarding acceptance proves local, dynamic, and remote data flow; local/dynamic disconnect
  cleanup; bind-conflict reporting; and cleanup of listeners started before a later rule fails.

## Deferred By Policy

- Authenticated proxies, TLS-to-proxy, PAC/WPAD, arbitrary `ProxyCommand`, UDP proxying, and
  automatic proxy fallback remain unsupported.
