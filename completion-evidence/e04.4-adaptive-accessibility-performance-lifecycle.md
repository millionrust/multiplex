# E04.4 adaptive accessibility, performance, and lifecycle acceptance

Date: 2026-08-29
Status: complete

## Delivered

- Added one canonical acceptance-v1 corpus shared by Rust, Swift, and Kotlin for
  compact/regular geometry, 10...32-point font bounds, 200% text scaling, bounded
  screen-reader output, 44-point/48-dp targets, and background cleanup decisions.
- Replaced hard-coded mobile terminal grid divisors with the tested policy. Both native
  terminals now persist user-selected text size, resize from measured density-aware
  dimensions, and keep controls usable through compact widths and expanded text.
- Exposed one bounded terminal-output accessibility element rather than every rendered
  cell. Privacy-covered terminals are removed from the accessibility tree, writer and
  connection states retain visible text/icons, and output frames are not live-announced.
- Made Android backgrounding cancel delayed resize, clear pending resize and unconfirmed
  paste, invalidate writer state, cover terminal content, and release a held lease before
  disconnect. Swift uses the same tested decision and already performs those transitions.
- Added `terminal-acceptance` verification stages. They retain prior v1/v2 rendering,
  interaction, writer, bounds, route-isolation, and no-legacy-SSH checks.
