# E07.8 Resilient Bounded SFTP Transfer Manager

- Status: complete
- Completed: 2026-08-30
- Branch: `test`
- Implementation commit: `469b6cb feat(sftp): add resilient bounded transfer manager`

## Delivered

- Replaced ad hoc upload/download workers with one process-wide manager capped at three active and
  32 queued jobs, with fallible worker startup and immediate queued cancellation.
- Added typed queue, start, monotonic progress, conflict, skip, cancellation, failure, and verified
  completion events with direction, exact bytes, resume offset, SHA-256, and cleanup truth.
- Streamed local and remote I/O in 256 KiB chunks with a fixed 8 GiB ceiling, bounded connection and
  channel operations, and cancellation during queued, connecting, and active states.
- Added operation-owned local/remote staging and backups, destination/source revalidation, safe
  no-overwrite local publication, explicit Ask/Replace/Skip/Resume policy, prefix validation, and
  retained staging after cancellation or identity refusal.
- Added the workspace Files toolbar and lifecycle panel with upload/download, browse, refresh,
  delete, progress, cancellation, conflict decisions, retry/resume, cleanup warning, and checksum.
- Kept directory and transfer operation correlation independent so refresh/navigation cannot make
  valid progress stale or let unrelated list failures overwrite transfer state.
- Removed the superseded transfer wrappers/events, documented the contract in
  `docs/decisions/sftp-transfer-manager.md`, and added
  `scripts/verify-sftp-transfer-manager.sh`.

## Acceptance Evidence

- Live Docker upload/download proves streamed progress, equal upload/download SHA-256, and existing
  directory/delete compatibility.
- Live conflict acceptance proves Ask and Skip do not mutate the destination, Replace publishes only
  verified staging, matching upload/download staging resumes at 300,000 bytes, and mismatched
  prefixes preserve the destination and staging.
- Live active cancellation proves a 64 MiB replacement can be cancelled after start without
  clobbering the existing remote destination; the operation-owned partial remains resumable.
- Unit acceptance proves global active/queue limits, queue rejection and slot reuse, cancellation of
  a stalled SSH handshake, deterministic step timeout, 8 GiB rejection, symlink rejection,
  operation-scoped backup handling, destination-race refusal, and no full-file buffering.
- Rendered GPUI acceptance drives the real dialog-backed Upload and Download actions and observes
  verified completion plus a 64-character checksum for both directions.
