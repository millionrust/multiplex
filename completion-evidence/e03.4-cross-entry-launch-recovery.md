# E03.4 Cross-entry launch and recovery completion evidence

## Result

Activity, Sessions, and the global command palette now resolve existing typed Session
IDs through one entry helper. Active durable Sessions focus an existing pane or attach
one pane; repeated opens do not create another pane or metadata record. Archived
Sessions and the palette's Show archive action open the unified Sessions archive.
Stale Activity links also return users to Sessions with the existing truthful stale-link
message.

Projects and preset search results continue to use the existing reviewed Project launch
and SessionCoordinator path. Connections continue to stage the selected saved profile
through the existing connection dialog and do not manufacture a typed Session before a
real launch. Resume remains limited to the frozen exact Codex contract.

Implementation commit: `59764d0` (`feat(sessions): unify cross-entry recovery`).

## Acceptance mapping

- Activity deep links, the Sessions Open action, and palette Session results all call
  `open_session_from_entry` with the original `HostedSessionId`.
- Reopening an already represented active Session focuses or retries its existing pane;
  the cross-entry test proves one pane and one authoritative metadata record remain.
- Archived Session results and Show archive route to `NavSection::Sessions`, not the old
  Project-owned sidebar route, and create no pane or record.
- The reviewed Project launch test proves exactly one typed Session record is created and
  literal initial input remains non-shell-parsed.
- The Connections test proves one saved profile is staged for review without creating a
  fake typed Session or terminal pane.
- Existing Activity, global-palette, Session resume, lifecycle, host recovery, and full
  workspace suites cover stale, unavailable, unsupported, reconnect, and recovery states.
- No Session ID, store, resume heuristic, process owner, protocol, or mobile behavior was
  added.
