## Result

One non-GPUI `SessionCoordinator` now owns the durable Session event sink and is the
only application-layer entry point that starts a durable Session worker. New launches,
exact agent resumes, saved-session restores, and retries all use typed launch or attach
requests that map into the existing `hosted_session.rs` process adapter.

## Delivered

- Added a closed launch/attach request boundary with constructors that prevent invalid
  launch-state combinations.
- Preserved Session identity, runtime and Session paths, replay watermark, occupant
  generation, launch configuration, runtime detection, and continuity commit data.
- Kept launch replay at sequence zero while attach preserves its supplied watermark.
- Boxed the larger launch payload so attach requests do not inherit its enum footprint.
- Added source-boundary coverage that rejects any direct durable worker start from
  another `src/ui/app` module.
- Added an architecture check that keeps the coordinator independent of GPUI.
- Left `hosted_session.rs` as the low-level Host/process adapter and made no protocol,
  persistence-schema, UI, or product-behavior changes.
