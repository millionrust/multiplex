Slate

Slate is the visual system for the TermiRust desktop client. Every surface is a flat pane split by hairlines, type sits at 12 and 13 px, and color is saved for state. This page is the source for the token file and the Rust component library. Each value below maps to a key in design/tokens.toml.

Specimens on this page render from the same token data they document. Use Specimen theme at the top to preview Dark, Light, High contrast, and Recording. The System theme follows the OS and resolves to Dark or Light.

Principles

Six rules decide the close calls. When a component spec and a principle disagree, the principle wins and the spec gets fixed.

Panes, not cardsRegions are full-bleed and split by 1 px hairlines. Only things you can pick up or open, like host cards, dialogs, and menus, get a fill and a radius.
Color means stateNeutrals carry the interface. Green, amber, red, and blue appear only when something is live, needs attention, failed, or is busy. The accent never fills a button.
Weight over hueThe primary action is the same neutral button as the others, set in semibold. Hierarchy comes from type weight and position, not from colored fills.
Dense, never crampedRows are 28 to 32 px, controls 22 to 26 px, and body text 13 px. Pointer targets stay at least 24 px, and nothing essential falls below 4.5:1 contrast.
The terminal is the heroChrome recedes around terminal panes. Panes get the most space, the most stable geometry, and no decoration that moves while output streams.
Shape plus colorEvery status has a glyph shape and a text label as well as a color, so state survives color blindness, grayscale recordings, and high-contrast mode.

Color

Semantic tokens only. Components never reference a hex value. Each token lists its value in every theme, its role, and, for text and status tokens, the measured contrast against the surface it sits on in the previewed theme.

Group tints

Host tiles take the group color for the glyph and the same color at 14% opacity for the tile fill. Groups are a user-facing grouping, so they sit outside the status system and never imply health.

Terminal palette

The 16 ANSI colors, foreground, cursor, and selection. Normal colors reuse the status hues so a green 200 in a log reads the same as a green Live dot. Bright colors are lifted about 12% in lightness.

Typography

Two families, both system faces, so the app matches the OS and needs no bundled fonts. UI text uses system-ui: SF Pro on macOS, Segoe UI Variable on Windows, and the desktop default on Linux. Terminal and technical text use system-monospace: SF Mono, Cascadia Mono, or DejaVu Sans Mono.

Sizes are logical pixels. Line heights snap to whole pixels except the terminal, which uses a 1.4 ratio so cell height scales with the font-size setting.

Spacing

A 4 px base with a 2 px half-step for optical fixes. Components take spacing from this scale. The named tokens at the bottom are the few measured exceptions the shell needs.

Radius and borders

Radii stay small so panes read as one surface. Controls are 4 px, floating objects are 6 px, and pills are reserved for toggles and counts. Borders are 1 px everywhere except High contrast, where every hairline becomes 2 px.

Elevation and layers

Panes never cast shadows. Elevation is only for things that float above the panes: menus, the palette, dialogs, tooltips, and toasts. Layer order is fixed so a toast can never hide a security prompt.

Motion

Motion confirms an action and then gets out of the way. Nothing animates while terminal output streams, and everything drops to instant when the OS asks for reduced motion.

Icons

Line icons on a 16 unit grid with a 1.4 stroke, round caps, and round joins. Icons inherit text color. They take the accent only when they mark the active item. Rendered at 12, 14, or 16 px.

Status system

Eight kinds cover every state the app reports, from hosts and sessions to agents and devices. Each kind is a triple of shape, color token, and label, so no state is communicated by color alone. The glyph is 7 px inside a 12 px box and sits 7 px before its label.

Connection states

Hosts and sessions map their lifecycle onto the status kinds. The label is the word the interface shows.

The default window is 1280 by 840 and the minimum is 960 by 640. Fixed bars take their height from layout tokens. Everything between them is panes. The diagram is drawn to scale.

Accessibility

Accessibility is part of each token rather than a separate mode. The contrast columns in Color are measured live for the previewed theme.

AreaRequirement
Text contrastEvery text and status token reaches 4.5:1 on canvas, surface, elevated, and chrome in all four themes. Faint text is never placed on bg.selected, where it drops to 4.3:1.
Non-text contrastFocus rings and status glyphs reach 3:1 against their surface. Hairline borders are decorative, so every control is also identified by its label and fill, never by its outline alone. High contrast makes borders white and doubles them to 2 px.
FocusA 2 px focus ring, offset 1 px, shows on keyboard focus only. Overlays trap focus and return it on close. Terminal panes show focus with the lit header and the solid cursor.
TargetsPointer targets are at least 24 × 24, meeting WCAG 2.2 target size (minimum). Row actions and close buttons get invisible padding up to 24. The mobile apps keep 44.
StateStatus always pairs a shape and a label with its color. Selection uses a fill plus a weight change, never color alone.
MotionThe OS reduced-motion setting drops every duration to motion.instant. The busy spinner steps instead of sweeping.
Screen readersRows expose name, address, and status in that order. Tabs report their pane count. Toasts are polite live-region announcements. Security dialogs are assertive.
Recording themeLower saturation and lifted darks so screen recordings and video calls keep status colors apart after compression.

Build

Token changes

Every key that is new or whose dark value differs from today's design/tokens.toml. Applying these is step one of the Rust work. The generated contract and the design-token gate then flag every hard-coded value that no longer matches.

Newkey does not exist yetChangedkey exists with a different value

Rust handoff

Slate becomes a styled component crate on top of gpui-base, fed by the token contract the app already generates. It replaces gpui-component, which today only supplies buttons, inputs, scroll areas, and layout helpers.

Prerequisite

gpui-base 0.6 builds on the gpui-pre 0.3 snapshots, not the gpui 0.2.2 crate the desktop app uses now. The GPUI upgrade has to land first, in its own spike branch, before any Slate component can depend on gpui-base.

API shape

Builders in the gpui style, tokens resolved from the active theme, and no styling escape hatches on the public surface. A screen that needs a new look needs a new variant here first.

// A strong neutral button with a leading icon
Button::new("new-host")
    .label("New Host")
    .icon(Icon::Plus)
    .weight(ButtonWeight::Strong)          // Default | Strong
    .size(ControlSize::Default)            // Small 22 | Default 26 | Large 36
    .on_click(cx.listener(|this, _, window, cx| this.open_new_host(window, cx)))

// Status is always glyph + label + token color
StatusGlyph::new(StatusKind::Done).label("Live")

// Terminal tab body: app-owned split tree, Slate draws panes and dividers
SplitPanes::new(workspace.split_tree())
    .max_panes(MAX_SPLIT_PANES)            // 4
    .ratio_range(0.15..=0.85)
    .pane(|pane, window, cx| TerminalPane::new(pane).into_any_element())
    .on_resize(cx.listener(Self::resize_split))
    .on_drop(cx.listener(Self::drop_into_split))   // edge + source (tab or pane)
