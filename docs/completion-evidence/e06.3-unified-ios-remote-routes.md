# E06.3 unified iOS and iPadOS remote routes

Date: 2026-08-30
Status: complete

## Delivered

- Ported the canonical remote-route policy and fail-closed state machine to strict Swift 6,
  covering local IPC policy plus the three Apple-applicable routes: private LAN/VPN,
  user-provided SSH, and optional self-hosted relay.
- Added an Apple coordinator with explicit selection, persisted choice, visible unavailable,
  degraded, disabled, and revoked states, bounded same-route reconnect, deterministic
  cancellation, writer release, and command-ID reconciliation for unknown mutations.
- Preserved unavailable persisted choices instead of silently falling back to LAN. Switching
  always requires confirmation, closes only the source, and never starts the target itself.
- Added route-keyed `ControllerConnecting` ownership. Fleet refresh, terminal attach,
  cancellation, and retry use only the selected transport; injected SSH/relay fixtures are
  never aliased to the production LAN actor.
- Added responsive SwiftUI Device route rows with selected, ready, reconnecting, degraded,
  revoked, and not-configured status plus an explicit switch confirmation.
- Added validated route configuration descriptors containing only credential references.
  SSH authentication and relay admission material use route-, host-, and purpose-scoped
  Keychain accounts with this-device-only accessibility and bounded secret size.
- Kept direct SSH Connections separate from Host-owned Device Sessions and retained all E04
  terminal and E05 cross-route lifecycle contracts.

## Runtime And Product Limits

No eligible iPhone simulator or generic iOS destination is installed in this Xcode, so the
XCTest bundles were strictly typechecked but could not execute. The pure canonical runner did
execute. Release CI must run `scripts/verify-ios-unified-routes.sh --require-runtime`.

The production Device transport set currently installs private LAN/VPN only. Direct SSH is a
working Connection route. SSH Controller and self-hosted relay remain visibly unconfigured
unless dedicated native `ControllerConnecting` adapters are supplied; the app does not relabel
LAN or silently fall back. E06.5 retains this limitation in cross-platform acceptance rather
than claiming unavailable network coverage.
